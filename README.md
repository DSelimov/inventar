# Инвентар

Универсална система за инвентар за всякакъв тип бизнес: дефинирайте собствени
категории с персонализирани полета, следете артикули и наличности, получавайте и
изпращайте стока, групирайте артикули в колекции и дръжте всичко в календар.

## Технологии

| Слой | Избор | Защо |
|---|---|---|
| Език | **TypeScript** навсякъде | един език за интерфейс, сървър и схема на базата |
| Framework | **Next.js 16** (App Router, Server Actions, Route Handlers) | страници, сървърна логика и REST API в един проект |
| База данни | **PostgreSQL 16** чрез **Drizzle ORM** (node-postgres) | транзакции, индекси, готова за много потребители и организации |
| Стилове | **Tailwind CSS 4** | малка, консистентна дизайн система в `src/app/globals.css` |
| Други | lucide-react (икони), date-fns (дати, bg локал), html5-qrcode (камера) | |

## Стартиране

```bash
pnpm install
cp .env.example .env          # DATABASE_URL + APP_SECRET
docker compose up -d postgres # PostgreSQL на порт 5440
pnpm db:push                  # създава таблиците
pnpm db:seed                  # демо данни (по избор)
pnpm dev                      # http://localhost:3000
```

Демо вход след `db:seed`: **admin@demo.bg / demo1234** (собственик) и **sklad@demo.bg / demo1234** (служител).

Други скриптове: `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm db:studio`
(разглеждане на базата), `pnpm db:reset` (push + seed).

## Функционалности

### Основа
- **Табло**: показатели, ниска наличност с бутон за поръчка, последни движения, следващите 7 дни,
  стойност по категория и по локация, изтичащи партиди.
- **Категории** с **персонализирани полета** (текст, число, дата, избор, да/не, „задължително“).
- **Артикули**: код, баркод, описание, минимум, мерна единица, цени, архивиране, динамични полета,
  **варианти** (размер/цвят със собствен код и наличност), **партиди със срок на годност** или
  **серийни номера** (FEFO подредба, предупреждения за изтичане), пълна складова история с потребител.
- **Локации**: няколко склада/магазина, наличност по локация, **трансфери** между локации, локация
  по подразбиране.
- **Складови движения**: приход / разход / точно количество / трансфер; всяка промяна с причина и потребител.
- **Партньори**: доставчици и клиенти с контакти, ДДС номер, срок на доставка, история.
- **Поръчки**: за доставка (от доставчик) и клиентски; чернова → потвърдена → частично → изпълнена;
  **пратка за оставащото** с един бутон, частични доставки и остатъци.
- **Пратки**: входящи/изходящи с редове, партиди/серийни номера по ред, локация, партньор, куриер,
  проследяване; доставката прилага наличността в една транзакция и обновява поръчката.
- **Колекции**: свободно групиране на артикули.
- **Календар**: очаквани пратки, изтичащи партиди, собствени събития, напомняния, крайни срокове.
- **Сканиране**: камера на телефона (html5-qrcode) или USB/Bluetooth скенер; бърз приход/разход;
  непознат баркод → създаване на артикул с него.

### Анализи (Отчети)
Параметри по организация (Настройки): прозорец за анализ, дни за залежала стока, срок на доставка,
буфер за сигурност, целеви марж. Отчети: стойност на склада по месеци, оборот и марж по категория,
най-продавани, **предложения за поръчка** (средна дневна консумация × покритие + минимум − наличност −
очаквано), залежала стока, възраст на наличността, изтичащи партиди.

### Потребители и организации
- Вход с имейл и парола (scrypt, сесии в базата, httpOnly cookie). SSO не е включен на този етап.
- **Роли**: собственик, администратор, мениджър, служител, само четене; проверка на всяко действие.
- **Няколко организации** (multi-tenant): всички данни са разделени по организация; един потребител
  може да е член на няколко и да превключва от страничното меню.
- **Одит**: кой какво е променил, с детайли.

### Интеграции
- **CSV импорт** на артикули (преглед преди запис, upsert по код, автоматични категории, наличности по
  локация) и **CSV експорт** на артикули, наличности по локации и движения.
- **REST API** `/api/v1/*` с API ключове (четене / запис) — артикули, наличности, движения, пратки
  (вкл. смяна на статус), поръчки, локации, партньори, категории. Списъкът е в Настройки › API.
- **Webhooks**: POST с HMAC-SHA256 подпис за събития (създаден/променен артикул, ниска наличност,
  движение, пратка, поръчка), с журнал на доставките и тестово събитие.

## Структура на проекта

```
src/
  app/            маршрути (по една папка на страница), layout, глобални стилове
  components/
    layout/       странично меню
    ui/           бутони, полета, карти, етикети, таблици, празни състояния
    items/        ItemForm (динамични полета)
    shipments/    ShipmentForm (динамични редове)
    orders/, partners/, scan/, settings/, auth/
  db/             schema.ts (Drizzle, PostgreSQL), index.ts (pool), seed.ts
  lib/
    actions/      server actions (всички записи са тук; всяко действие проверява роля)
    queries.ts    всички четения (винаги с organizationId)
    stock.ts      двигател на наличностите: локации, партиди, серийни номера, трансфери
    shipment-service.ts  доставка на пратка (общо за UI и API)
    reports.ts    изчисления за Отчети
    auth.ts, permissions.ts, audit.ts, webhooks.ts, api.ts, csv.ts, settings.ts, forms.ts, utils.ts
  app/api/        export/[kind] (CSV), v1/* (REST API)
```

Правила: страниците са server components, които четат чрез `lib/queries.ts` и
променят чрез `lib/actions/*`. Само формите, които изискват интерактивност, са
client components.
